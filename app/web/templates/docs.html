Documentación

Tu primera request en menos de un minuto. Para detalles completos de cada endpoint, mira la reference en Swagger.

Empieza en 60 segundos

Tres pasos para tu primera extracción.

1

Crea una cuenta gratis

Solo necesitas un email. Verifica tu correo y obtienes tu primera API key automáticamente.

Crear cuenta
2

Copia tu API key

La API key te aparece al verificar el email y en el dashboard al crear una nueva. Empieza con psr_ y se muestra una sola vez, guárdala en un lugar seguro.

3

Manda tu primera request

POST a /api/v1/extract con la URL del documento y el schema. Elige tu lenguaje: 

curl -X POST https://parsero-production.up.railway.app/api/v1/extract \
  -H "Authorization: Bearer psr_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "document_url": "https://example.com/factura.pdf",
    "schema_type": "invoice"
  }'
import httpx

response = httpx.post(
    "https://parsero-production.up.railway.app/api/v1/extract",
    headers={"Authorization": "Bearer psr_xxx"},
    json={
        "document_url": "https://example.com/factura.pdf",
        "schema_type": "invoice",
    },
    timeout=30,
)
print(response.json())
const response = await fetch(
  "https://parsero-production.up.railway.app/api/v1/extract",
  {
    method: "POST",
    headers: {
      "Authorization": "Bearer psr_xxx",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      document_url: "https://example.com/factura.pdf",
      schema_type: "invoice",
    }),
  }
);
const data = await response.json();
console.log(data);

Reemplaza psr_xxx con tu API key real.

Schemas disponibles

El campo schema_type determina la estructura del JSON. Los modelos completos están en app/schemas/extraction_outputs.py .

invoice Facturas y notas de venta +

Campos principales:

  • invoice_number, issue_date, due_date
  • vendor (name, email, tax_id, address)
  • customer (name, email, tax_id, address)
  • line_items[] (description, quantity, unit_price, total)
  • subtotal, tax, total, currency
  • payment_terms
cv Currículums y resumes +

Campos principales:

  • personal (full_name, email, phone, location)
  • experience[] (company, job_title, dates, achievements)
  • education[] (institution, degree, field, dates)
  • skills[]
  • certifications[] (name, issuer, date)
  • languages[] (language, proficiency)
receipt Recibos y tickets de compra +

Campos principales:

  • merchant (name, address, tax_id)
  • transaction_date, transaction_time
  • line_items[] (description, quantity, unit_price)
  • subtotal, tax, total, currency
  • payment_method, transaction_id
  • loyalty_program

Manejo de errores

Todos los errores devuelven un JSON con el campo detail describiendo el problema.

Código Significado Qué hacer
400 Documento inválido o no descargable. Verifica la URL, el tamaño (max 5MB) y el formato (PDF/text).
401 API key faltante, inválida o revocada. Genera una nueva key desde el dashboard.
422 El LLM devolvió JSON que no cumple el schema. Reintenta. Si persiste, el documento puede no ser del tipo indicado.
429 Rate limit excedido para tu plan. Espera lo indicado en Retry-After o actualiza de plan.
502 Error del proveedor LLM (timeout, red). Reintenta con backoff. Es transitorio.

Conceptos clave

Tres cosas que vale la pena saber.

Cache automático

El cache key es (tu_tenant, hash_del_documento, schema_type). Si pides el mismo documento con el mismo schema dos veces, la segunda viene del cache y no consume tokens nuevos.

Rate limiting

Bucket por minuto en Redis. Cuando excedes el límite del plan, recibes 429 con header Retry-After: 60. Sin overage charges.

Seguridad de las keys

Solo guardamos el hash SHA-256 de cada key. La key en claro se muestra una vez al crearla y nunca más. Si la pierdes, revócala y genera una nueva.
